## Summary

First bug-fix release after the 1.0.0 public launch. Two user-visible changes
and one new setting:

1. Restores API connectivity — 1.0.0 shipped with an empty Rejseplanen API
   key due to a build-setting substitution that only worked during debug
   runs-from-Xcode, so every installed copy of 1.0.0 silently failed to load
   departures. This release bakes the real key into the Info.plist at build
   time for all configurations.
2. Adds an **offline mode** that shows time-shifted departures from a local
   cache when the network is unreachable. Cache is keyed by
   `(commuteScheduleId, dayType)` so weekday / Saturday / Sunday are isolated
   from each other.
3. Adds a **Clear offline cache** button under Settings → Storage.

Internal-only changes (not mentioned in release notes):

- Silenced three Swift 6 `"sending 'activity' risks data race"` concurrency
  warnings on Live Activity update calls via `@preconcurrency import
  ActivityKit` and extraction of the ActivityKit I/O into nonisolated static
  helpers.
- `SettingsView`'s About row now reads the version from `Bundle.main` so it
  can no longer drift from the shipped Info.plist.
- Dead `PendlerUITests` target and missing `Debug.xcconfig` reference removed
  from `project.yml` so `xcodegen generate` runs cleanly again.

## Known issues / follow-ups

- Rejseplanen API key is still committed to `project.yml` and baked into the
  `.xcodeproj`. Acceptable short-term because the source repo is private and
  the key is a rate-limit credential, not a security credential. Rotation +
  Xcode Cloud env-var injection via `ci_scripts/ci_post_clone.sh` is the
  long-term plan; postponed to a later release.
- Widget extension still uses the older `WidgetDepartureCache` path for its
  own offline fallback. Unifying it with `DepartureOfflineCache` would give
  the widget the same day-type-aware shift logic, but is out of scope for
  1.0.1.
- `PendlerUITests` target was removed because its source directory no longer
  exists. A proper unit-test target (`PendlerTests`) would be a good addition
  — `DepartureOfflineCache.shift()` and `DayType.of()` are pure functions and
  very easy to test.
